# Права пользователей

«Администрирование» → таблица пользователей → кнопка в столбце **«Права»**. Для каждого раздела CRM две галочки:

- **Видит** — раздел есть в меню и открывается;
- **Изменяет** — может добавлять, менять и удалять записи. Пока есть только у «Отправлений» (вместе с «Архивом» и карточкой отправления) и «Слежки авто».

Быстрые кнопки «Всё», «Только просмотр», «Ничего». После «Сохранить права» меню пользователя меняется сразу, без перезахода.

Пока права не сохранены, действует роль, как раньше: логистика видит и меняет всё, наблюдатель всё видит, но ничего не меняет, региональный менеджер видит «Региональные рейсы» и «Справочники». Сохранённые права заменяют роль. «Вернуть права роли» снимает ручную настройку. Владелец CRM всегда имеет полный доступ, гость ничего не может менять.

Изменения запрещают правила Firestore и сервер (`crmApi`), а не только интерфейс. Сам изменить свои права пользователь не может. Скрытие раздела убирает его из меню. Данные, которые читаются всеми вошедшими (например, список отправлений), Firestore по-прежнему отдаёт любому вошедшему пользователю.

## Публикация

1. AI Studio: подтянуть `main` и нажать Publish.
2. Cloud Shell — правила и сервер одной командой:

```sh
cd ~/AILog && git pull --ff-only origin main && npx -y firebase-tools deploy --only firestore:rules,functions:crm:crmApi --project logisticsapp-216d5
```

Проверка: `npm run test:access`.

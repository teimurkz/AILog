# Интерфейс CRM

Светлый рабочий интерфейс с тёмным меню, спокойными синими акцентами, едиными панелями и отступами. Общие правила находятся в `src/crm.css`, размеры скруглений и шрифты — в `src/index.css`.

Таблицы используют `ResponsiveTable`: на узком экране те же записи становятся карточками с подписями полей. Компонент сохраняет исходные элементы управления, обработчики, порядок полей и объединённые ячейки итогов. Горизонтальная прокрутка для чтения записей не требуется. Длинные складские списки допускают вертикальную прокрутку. У отправлений сохранены существующие раскрывающиеся карточки.

Для новых экранов используйте `crm-page-header`, `crm-filters`, `crm-stats`. Для окон — `crm-dialog-overlay` и `crm-dialog`. Не задавайте минимальную ширину таблицы больше доступной области. Не добавляйте `transform` или layout containment на общий контейнер страниц: это меняет расположение вложенных фиксированных окон.

## Проверка от 15.09.2026

В изолированном Chrome с тестовыми записями проверены 12 разделов: обзор, отправления, региональные заявки, справочники, склады, рассылка, аналитика, сроки КУСТО, печати, архив, существующий экран автопарка и администрирование.

- 84 проверки границ элементов: каждый раздел при ширине 320, 390, 768, 1024, 1280, 1440 и 1920 px. Выходов за экран и горизонтальной прокрутки таблиц не обнаружено.
- Открытие форм отправления, региональной заявки, назначения машины, получателя рассылки, сопоставления колонок; массовый выбор, карточка отправления и поиск. Проверены также при высоте экрана 390 px.
- Вкладки справочников, канбан, панель Outlook / Power Automate, предварительный просмотр тестового Excel без импорта в базу, экран входа, страница водителя и направление интерфейса справа налево.
- Разворот карты в полный экран и возврат по Escape при 390 × 844 и 844 × 390 px.
- Проверка типов и сборка приложения прошли. Три теста адаптивной таблицы, семь тестов диагностики рассылки и шесть тестов истории GPS прошли.

Повторяемые проверки кода:

```bash
npm run lint
npm run test:layout
node --import tsx --test tests/mailing-diagnostics.test.tsx tests/gps-trail.test.ts
npm run build
```

Проверка вёрстки выполнялась с подменёнными данными и отключёнными внешними запросами. Она не является проверкой реальной отправки писем, входа в Google или получения GPS с телефона. Изменений схемы Firebase и миграций данных нет.

## Публикация

Получите изменения из `origin/main` в AI Studio, затем опубликуйте приложение. Это обновление интерфейса; повторная публикация Firebase Functions для него не требуется. Существующую конфигурацию Firebase и именованную базу оставьте прежними.

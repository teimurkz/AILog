# Слежка авто

Раздел «Слежка авто» заменяет Excel-таблицу по фурам, которые уже приехали на СВХ. Этапы по умолчанию: «Прибыла на СВХ» → «Выгружена на СВХ» → «Перемещена на склад». Кнопка **«Этапы»** добавляет, переименовывает, удаляет и переставляет этапы; двойной клик по вкладке тоже переименовывает её. У каждого этапа свой столбец с датой: заполненная дата более позднего этапа переводит фуру дальше.

Данные хранятся в Firestore проекта `logisticsapp-216d5` (именованная база из `firebase.json`):

- `truck_tracking` — фуры: инвойс, наименование, даты этапов `stageDates`, статус, комментарий, кто и когда изменил;
- `truck_tracking_stages` — этапы, общие для всей команды. Пока их никто не менял, используются этапы по умолчанию.

Читать могут все вошедшие пользователи, изменять — роли «логистика» и «админ».

## Публикация

Интерфейс: подтянуть `main` в AI Studio и опубликовать как обычно. Серверная функция и миграция данных не нужны.

Правила доступа — **один раз**, потому что подтягивание кода в AI Studio не публикует `firestore.rules`. Пока правила не опубликованы, раздел показывает это сообщение и ту же команду. В [Google Cloud Shell](https://shell.cloud.google.com/) под рабочим аккаунтом выполнить:

```sh
(test -d AILog || git clone https://github.com/teimurkz/AILog.git) && cd AILog && git pull --ff-only origin main && npx -y firebase-tools deploy --only firestore:rules --project logisticsapp-216d5
```

Если Firebase CLI попросит войти, выполнить `npx -y firebase-tools login --no-localhost` и повторить команду.

Команда публикует весь файл `firestore.rules` из `main` — тот же, что публиковался для GPS, Outlook и Power Automate, плюс два новых блока `truck_tracking` и `truck_tracking_stages`. Остальные коллекции и данные не меняются. После публикации нажать «Повторить» в разделе или обновить страницу.

Проверка логики, импорта из Excel и экспорта: `npm run test:truck-tracking`.

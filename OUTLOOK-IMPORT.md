# Отправления из Outlook

CRM получает письма выбранного логиста через Microsoft Graph. Firebase-функция
`outlookShipments` проверяет почту каждые 5 минут, даже когда CRM закрыта.
Подключение и журнал импорта доступны администратору в разделе **Отправления → Почта Outlook**.

## Однократная настройка Microsoft 365

В рабочей организации Microsoft Entra зарегистрируйте приложение **Silk Road CRM — документы из Outlook**.
Если у сотрудника нет права регистрировать приложения, этот шаг выполняет IT-администратор организации.

1. Откройте [Microsoft Entra](https://entra.microsoft.com/) → **App registrations / Регистрации приложений** → **New registration**.
2. Выберите учётные записи **только этой организации** (single tenant). Redirect URI для входа по коду не требуется.
3. Скопируйте **Application (client) ID** и **Directory (tenant) ID** со страницы Overview.
4. В **Authentication → Advanced settings** включите **Allow public client flows** и сохраните.
5. В **API permissions → Microsoft Graph → Delegated permissions** добавьте `Mail.Read`, `User.Read`, `offline_access`.
6. Если политика компании требует согласования, администратор Microsoft 365 должен разрешить эти делегированные права.

Используется вход по одноразовому коду Microsoft. Client Secret, пароль почты,
права `Mail.Send`, `Mail.ReadWrite` и application permissions не нужны.
Если политика организации запрещает device code flow, её не следует обходить:
потребуется согласовать разрешённый способ входа с IT и адаптировать интеграцию к нему.

Официальные инструкции:
[вход по коду](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-device-code),
[настройка public client](https://learn.microsoft.com/en-us/entra/identity-platform/scenario-desktop-app-configuration).

## Публикация в существующий Firebase

В авторизованном Cloud Shell, из каталога актуального репозитория:

```bash
git pull --ff-only origin main &&
npm ci &&
npm --prefix functions ci &&
firebase deploy --only functions:crm:crmApi,functions:crm:outlookShipments,firestore:rules --project logisticsapp-216d5
```

Используются текущий проект, существующая именованная база Firestore и Storage.
Команда не переносит и не очищает данные. Фронтенд затем обновляется из этого же
коммита в AI Studio или штатным способом публикации CRM.

Правила Firestore нужно опубликовать **до подключения почты**: коллекции
`outlook_private`, `outlook_imports` и `outlook_invoice_index` доступны только серверу.
Запрещено добавлять к ним общий разрешающий wildcard: правила с `allow: false`
не перекрывают другой совпавший `allow: true`.

## Подключение в CRM

1. Войдите в CRM как администратор. Откройте **Отправления → Почта Outlook**.
2. Введите Tenant ID, Client ID, рабочую почту и адрес логиста.
3. Выберите дату получения писем, начиная с которой нужен импорт, и ожидаемый срок перевозки. Даты периода задаются по времени Алматы.
4. Нажмите **Подключить Outlook**, откройте Microsoft и введите показанный одноразовый код.
5. Войдите именно под указанной рабочей почтой и подтвердите чтение. CRM проверит совпадение аккаунта.
6. Для проверки нажмите **Импортировать сейчас**. Одна проверка обрабатывает страницу до 10 писем. Если писем больше, повторите или включите автоматический импорт.
7. Включите флажок автоматического импорта и сохраните настройки. Через 5–10 минут должен появиться свежий сигнал службы.

Ручная проверка не выдаёт себя за сигнал планировщика. Если автоматический импорт
включён, но свежего сигнала нет, проверьте публикацию `outlookShipments` и связанное
задание Cloud Scheduler. Ошибка доступа Microsoft отображается отдельно.

## Правила создания отправлений

- Один инвойс — одна фура. Название отправления берётся из имени единственного Excel-вложения.
- Точки, дефисы и начальные нули сохраняются. Пробелы и регистр не создают другой инвойс.
- Поддерживается проверенный формат Solico: `Order Form` и `D CMR` внутри `.xlsx`.
  Проверяются имя заказа, полный номер инвойса, маршрут и номера машины, если они заполнены.
  Товарные позиции читаются из заполненных строк Order Form; служебные справочники не импортируются как груз.
- Начало отсчёта нового отправления — исходное `receivedDateTime` письма.
  Дата инвойса и дата загрузки из документов хранятся отдельно.
- Позднее письмо добавляет новые документы, сохраняя дату первого.
  Если специально импортирован более ранний период, начало отсчёта уточняется по самому раннему письму.
- При доставке счётчик останавливается на дате прибытия/выгрузки.
- Повторная обработка одного письма не создаёт второе отправление.
  Один и тот же файл не добавляется повторно; изменённый файл с прежним именем сохраняется отдельной версией.
- Если в CRM уже есть ровно одно отправление с таким именем инвойса, к нему добавляются документы.
  Его ID, статус, водитель, маршрут, даты и другие вручную заполненные поля сохраняются.
  Существующий ручной отсчёт не заменяется автоматически почтовым.
- До успешного сохранения всех документов и исходного письма новая карточка не создаётся.
- Письма без вложений пропускаются. Несколько Excel, отсутствие Excel, повреждённая таблица,
  несовпадение инвойсов или дубли в существующей CRM попадают в журнал **Нужна проверка**.

Письма выбираются по отправителю и дате во всём основном ящике, кроме папок
Deleted Items и Junk Email. Перемещения внутри ящика учитываются через immutable ID.
Для обычных повторных проверок используется перекрытие по дате в 24 часа;
после длительного сбоя обработка продолжается с сохранённой позиции.
Для писем, восстановленных из удаления позже этого окна, выберите более ранний период заново.
Отдельный online archive Microsoft 365 в этот импорт не входит.

## Документы и доступ

Все обычные файловые вложения сохраняются в Firebase Storage с исходными именами
в карточке. Полное письмо сохраняется как `.eml`, включая встроенную подпись.
Встроенные изображения не загромождают список документов. Вложенные письма и
ссылки на файлы вместо обычных вложений требуют ручной проверки.

Лимиты: 25 МБ на документ, 40 МБ на пакет, 10 МБ на Excel, до 100 вложений в письме.
Изображения и PDF сохраняются без OCR; макросы, формулы и текст письма не исполняются.
Письма CRM не отправляет, не удаляет и не помечает прочитанными.

Токены Microsoft и device codes хранятся только в серверной коллекции Firestore
с шифрованием Google Cloud при хранении. В браузер, журнал импорта, Git или локальные
JSON-файлы они не передаются. Доступ API дополнительно проверяет роль администратора.
Разрешение Microsoft `Mail.Read` относится к ящику; фильтр по отправителю применяет CRM.

Отключение почты удаляет сохранённый refresh token и выключает импорт.
Уже созданные отправления и документы остаются. Полностью отозвать ранее выданное
Microsoft-разрешение можно также в настройках приложений рабочего аккаунта.

## Проверки перед публикацией

```bash
npm run test:outlook
npm run lint
npm run lint:functions
npm run build:functions
npm run test:functions
npm run build
```

Тесты используют искусственные письма, локальное хранилище в памяти и подмену
Microsoft Graph. Они не подключаются к рабочей почте или Firebase.
